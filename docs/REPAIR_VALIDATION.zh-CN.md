# v0.4 局部修复实施与验收

验收日期：2026-09-07 至 2026-09-08。桌面交付目录：`pcb-weaver-system`；工作台：`http://127.0.0.1:8765`。

**结论：受限范围的铜线修复、持久化 MCP、原生复验和界面已经实施，小板真实验收通过；160 器件复杂板仍有 7 处未连接，不能标记为系统级布线或工业投产通过。**

## 已实现的链路

1. 从版本绑定、哈希验证过的 KiCad DRC 报告定位未连接对象，通过真实 UUID 对应网络。建议区域为报告对象位置外扩 3 mm，不冒充最近连接点或已经证明可行的路线。
2. 提交明确的目标网络、矩形范围、可选拆除 UUID 和轮数。默认只补线；最多 8 个网络、1000 个显式拆除对象、10 轮，单次路由最多 300 秒。锁定铜线、跨出范围的线段和不属于目标网络的铜线不能拆除。
3. 在独立临时副本上导出原生 DSN。已有铜线标记为受保护对象；规则、线宽、间距、层、网络和引脚定义不改变。
4. 调用现有 Freerouting；通过原有严格 KiCad 接口将 SES 导入空铜临时板，再从结果提取目标网络和区域内的新铜。区域外或非目标网络的新铜不采用，并记录数量。
5. 合并回原始板 AST，保留原器件、焊盘、网络、规则和所有未被允许拆除的铜线。结果写入新版本，原版不覆盖。
6. 对准确候选版本执行全板 KiCad DRC、ERC、原理图一致性、几何约束和持久化线宽检查。按网络比较未连接数量，拒绝新的 DRC/ERC 问题、非目标网络变化以及没有严格改善的候选。
7. 失败候选和运行证据保留；仅通过比较门禁才返回 `improved` 或 `repaired`。制造发布仍需独立执行原有新鲜验证与归档门禁。

这里的“局部”指**最终允许修改的范围**。当前路径搜索仍使用整板 DSN，并不是引擎内部只遍历目标区域/网络的专用求解器。没有实现自主选择阻挡物、自动 QFP/BGA 逃逸、阻抗/等长或 SI/PI 优化，也没有新的工业级路径搜索算法。

## 使用入口

工作台顶部扳手按钮“局部修复”读取真实候选，确认范围后提交后台任务。删除对象需要明确 ID 和确认。查看任务详情可读到比较结果和候选版本；网页关闭不停止持久化工作进程。

MCP 新增 `diagnose_pcb_repair` 和 `submit_pcb_repair`，共 21 个工具。后者只负责排队，必须运行 `Start-Platform.ps1` 或 `Start-Worker.ps1`。机器桥接 REST v1 本轮不开放修复，不能绕过本机受信任入口的范围确认。

状态含义：`improved` 表示未连接数下降但可能仍被制造门禁阻断；`repaired` 表示该候选原生检查通过，不是制造授权或实板认证；`blocked` 表示没有采用候选结果。

## 复杂板未通过

以原样复制的 `system-mcp-acceptance / r-9b5f5075e65e4931` 为来源，创建独立工程 `repair-system-v4-gpt2`，范围为 `[117,105,141,142]` mm，仅目标 `/GPT2`，没有允许拆除的铜线，也没有降低任何电气规则。

- 第一次在导出阶段发现单行序列化超过 1 MB，KiCad 不能加载。修复分行输出及普通小数格式后，原生加载恢复，AST 内容保持一致。
- 第二次发现 KiCad 原生 DSN 使用有限有效数字，9 个极短路径被表示为重合端点、另有 1 个路径含重复点。保留这些原生表示并单独计数，不删除原铜、不放宽线宽或间距；原始几何最终仍以源板为准。
- 扇出开启的真实布线达到时限，没有合格 SES/完整结束证据，正确阻断。[记录](validation/repair-system-v4-gpt2-cb45eaec.json)
- 根据日志再做一次关闭全板扇出的对照，仍达到时限，未采用候选。[记录](validation/repair-system-v4-gpt2-ffb73592.json)

原始复杂板仍是 **7 处未连接**，本轮没有证明其数量下降。Freerouting 日志中的待布线项与 KiCad 的未连接报告不是同一计数，不能混用来宣称改善。`toolchain.repair-no-fanout.json` 仅保留作失败对照配置，不是新的推荐默认。

## 安全复核

独立故障注入测试验证了：不得让警告级未连接和间距错误相互抵消；拒绝新的 ERC 警告或同数量但已变化的问题；原生阶段前后反复校验准备文件；重新验证基线证据；拒绝输出与已有输入的链接/别名。记录的哈希链用于本机完整性，不是外部签名的合规审计体系。

DSN 保护状态的来源阅读固定在 [Freerouting 1.9.0 Wiring.java](https://github.com/freerouting/freerouting/blob/c88ad67e6d7cdb83ad52589a84e43ef9fe1e8620/src/main/java/app/freerouting/designforms/specctra/Wiring.java)，不能据此推导所有版本行为。本机 2.4.1 的行为另外通过上述原生正/负例验证；最终原铜保留还由合并和 KiCad 门禁保证。KiCad 输出有限有效数字的实现见 [Specctra 输出定义](https://docs.kicad.org/doxygen/specctra_8h_source.html#l00162)。

下一项核心技术工作是实现引擎内部的目标网络搜索与局部阻挡物处理，减少整板搜索及交换格式量化带来的干扰，再扩大到不同真实板型的固定对照集。企业平台适配及实板验证仍未开展。
